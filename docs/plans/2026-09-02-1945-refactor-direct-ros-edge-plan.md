# Clean Direct ROS 2 Edge Workspace

## Goal Capsule

Make this repository one conventional ROS 2 Humble workspace rooted here. It contains exactly two source packages: `dji_edge_driver`, which receives the unchanged Android UDP/JSON/RTP contract directly and publishes ROS topics, and `dji_edge_mapper`, which consumes navigation, serves the static `.pcd` map, and publishes pose/path/TF. No standalone receiver, HTTP relay, loopback RTP relay, nested workspace, or third interface package remains.

## Fixed Architecture

```text
edge-matrice-transport/
  src/
    dji_edge_driver/        # Android UDP/RTP -> ROS images, telemetry, NavigationState, diagnostics
    dji_edge_mapper/        # NavigationState -> static map, TF, pose, path
  build/ install/ log/       # colcon generated; ignored
  docs/ README.md            # current protocol and operational docs only
```

```text
Android tablet
  UDP JSON 5500/5501/5502 + RTP Primary 5600 + RTP FPV 5610
       -> dji_edge_driver
           -> telemetry, NavigationState, diagnostics, Primary/FPV images
               -> dji_edge_mapper -> /map/cloud, pose, path, TF -> RViz
```

## Decisions

- The driver is the only owner of Android ingress, state/fragment reassembly, clock probes, RTP/GStreamer, evidence, and the measurement dashboard. GStreamer depayloads/decodes H.264; Python never does.
- The mapper is the only owner of WGS84-to-local projection, static point-cloud publication, pose/path/TF. RTK is preferred when valid/in-use; GPS never stops the path; local Z is aircraft-relative altitude.
- `NavigationState.msg` belongs to `dji_edge_driver`, because it is an internal contract of this two-package workspace.
- NDJSON stays always on; compressed raw RTP is explicit diagnostic capture only; rosbag2 remains separate.
- Primary and FPV native GStreamer preview windows start by default. The dashboard is measurements/configuration only, not a video renderer.
- Android ports/protocol are frozen: `5500`, `5501`, `5502`, `5600`, `5610`, payload type `96`.

## Keep / Delete Boundary

Keep and migrate:

- The tested protocol, state, clock, evidence, RTP/H.264 measurement behavior required by the direct driver.
- `deploy/protocol/v1/golden_packets.json` and protocol specification, relocated under the driver package as test/documentation inputs.
- The mapper source, `map_vis.pcd`, map metadata, mapper configuration, RViz configuration, and navigation semantics.
- One current README and this plan.

Delete after migration verification:

- `dji_edge_receiver/`, root Python tests, native CLI/config/service files, native dashboard assets, native bench/verification scripts, and all documentation that describes the legacy receiver/HTTP-relay architecture.
- The nested `ros2_ws/` directory after its two packages are promoted to root `src/`.
- Superseded dashboard and workspace-refactor plans, stale roadmaps, temporary caches, Python egg metadata, and runtime artifacts.

Do not delete the Android project or modify its contract. Do not delete the map or RViz assets.

## Implementation Units

### U1 — Normalize the workspace and package names

Move `ros2_ws/src/dji_edge_bridge` to `src/dji_edge_driver` and update the package name, node name, launch files, message namespace, configuration, Compose/aliases, and tests. Move `ros2_ws/src/dji_edge_mapper` to `src/dji_edge_mapper` without changing mapper behavior. Root `build/`, `install/`, and `log/` are generated by colcon and ignored.

Verify: `colcon build --symlink-install` discovers exactly `dji_edge_driver` and `dji_edge_mapper`; source/setup shows both packages; mapper smoke still publishes map/pose/path from controlled navigation input.

### U2 — Rebuild the direct driver as the sole ingress runtime

Replace the partial prototype with clean modules inside `src/dji_edge_driver`: protocol/state/clock/evidence core, category-specific UDP endpoints, active tablet clock pinger, ROS publisher node, direct GStreamer feed pipelines, per-feed metrics, optional raw RTP capture, and direct dashboard server. Maintain complete-sample state semantics and endpoint validation. Install Python modules through the CMake ROS package without a generated-message collision.

Verify: focused tests cover valid/invalid/fractional telemetry, sequence/fragment state, clock ready/unavailable, RTK/GPS selection, evidence failure, RTP metrics/capture framing, clean shutdown, and no legacy import/HTTP/relay port.

### U3 — Restore one operational Docker command and docs

Make Docker dependency-only and bind-mount this root workspace at `/workspace`; do not mount a legacy source tree. The normal `djiedge` command builds/sources as needed, starts driver plus mapper, dashboard, and both previews. Keep a separately named shell helper. Write one current guide covering setup, config, evidence, dashboard, bench, RViz, and shutdown.

Verify: headless launch smoke has no orphaned children or occupied ports after Ctrl-C; X11 run starts dashboard and two previews; dashboard Exit stops the same process tree.

### U4 — Retire legacy implementation and establish parity evidence

After U1-U3 builds/tests pass, remove the identified legacy files and stale docs. Run Primary bench first; FPV is either evidence-backed working or classified at the first failed boundary (Android emission, Edge receive, RTP validity, AU, decode, or image publish). No cleanup is based only on a window being blank.

Verify: repository tree contains only the two packages under `src/`; no legacy receiver import or HTTP relay reference remains; Primary and FPV results are recorded with Android pre-network versus Edge post-network labels.

## Verification Contract and Definition of Done

- Exactly two `package.xml` files exist under root `src/`: `dji_edge_driver` and `dji_edge_mapper`.
- Root `build/`, `install/`, `log/` are produced by Dockerized Humble colcon and are ignored.
- Driver directly owns the five Android ports and publishes navigation, raw telemetry, frame metadata, diagnostics, transport metrics, Primary images, and FPV images.
- Mapper preserves map/pose/path/TF behavior and continuous GPS fallback.
- No runtime dependency on `dji_edge_receiver`, `127.0.0.1:8088`, `5602`, `5612`, or nested `ros2_ws` remains.
- Automated Humble build/test and controlled launch/map smoke pass before hardware bench.
- Props-off hardware bench validates the delivered architecture and retains evidence. FPV may remain an Android producer issue, but its first failing boundary must be explicit.
