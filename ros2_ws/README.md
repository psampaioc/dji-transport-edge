# DJI Transport Edge — ROS 2 Humble workspace

This is the Dockerized ROS-side adapter for the native edge receiver. It does
not open DJI hardware, send flight commands, or replace the Android transport.

```text
Drone → Cendence → Android tablet → UDP → native dji-edge (Ubuntu)
                                         │ HTTP state + local RTP relays
                                         ▼
                              Docker Humble: dji_edge_bridge
                                         │ ROS topics
                              dji_edge_mapper → map, pose, path, TF
```

`dji-edge` remains native because it is the validated UDP/RTP, clock and
evidence boundary. The Humble container uses host networking to read
`http://127.0.0.1:8088/v1/state`, RTP relay `5602` (primary) and `5612` (FPV).
There is no SHM path, raw video file, or Python H.264 depayload in the live
path; the bridge's GStreamer appsink decodes H.264 into ROS images.

## Workspace layout

Only these source packages exist under `src/`:

- `dji_edge_bridge`: `NavigationState.msg`, telemetry/state adapter, GStreamer
  RTP-to-image bridge and diagnostics.
- `dji_edge_mapper`: copied map asset, point-cloud publisher, WGS84-to-local
  projection, pose/path and `map → dji_aircraft` TF.

`build/`, `install/`, and `log/` are generated by `colcon` in this directory,
on the host bind mount. They are intentionally ignored.

## Normal operator path

1. Start the native receiver on Ubuntu: `dji-edge`.
2. In another terminal, enter the ROS container: `djiedge`.
3. Inside it, build and start the complete pipeline:

   ```bash
   source /opt/ros/humble/setup.bash
   colcon build --symlink-install
   source install/setup.bash
   ros2 launch dji_edge_bridge dji_edge_bringup.launch.py
   ```

The `djiedge` alias works from any directory, mounts
`~/Workspaces/edge-matrice-transport/ros2_ws` at `/workspace`, and opens an
interactive Humble shell. Closing that shell stops its `--rm` container but
does not remove the host workspace or its colcon artifacts. `djiedgeplus`
attaches to the shell only while it is still running.

Build/rebuild the dependency image after Dockerfile changes with:

```bash
DJI_EDGE_WS="$HOME/Workspaces/edge-matrice-transport/ros2_ws" \
  docker compose -f "$HOME/Dockerfiles/docker-compose.yml" build dji_edge_humble
```

To use another checkout/location, set `DJI_EDGE_WS` to that checkout's
`ros2_ws` path before invoking the Compose service.

## Diagnostic alternatives

The normal launcher includes both packages. Use these only to isolate a fault:

```bash
ros2 launch dji_edge_bridge dji_edge_bridge.launch.py
ros2 launch dji_edge_mapper dji_edge_mapper.launch.py
rviz2 -d "$(ros2 pkg prefix dji_edge_mapper)/share/dji_edge_mapper/rviz/dji_edge_mapper.rviz"
```

The RViz configuration is the adapted copy of the mapper project's original
view: the map cloud, thick cyan path and red aircraft pose are preserved. Only
the topic names changed to the DJI edge contract. Its QoS is intentional:
`/map/cloud` and `/dji/navigation/path` use **Reliable + Transient Local + Keep
Last**, so a late RViz instance receives the map and current path; the live pose
and image panels use **Volatile + Best Effort + Keep Last** to favor freshness.

## Topics

| Topic | Type | Purpose |
| --- | --- | --- |
| `/dji/navigation/state` | `dji_edge_bridge/NavigationState` | Map-ready location; RTK preferred, GPS fallback. |
| `/dji/telemetry/flight` | `std_msgs/String` | Original normalized flight sample as compact JSON. |
| `/dji/telemetry/rtk` | `std_msgs/String` | Original normalized RTK sample as compact JSON. |
| `/dji/telemetry/gimbal` | `std_msgs/String` | Original normalized gimbal samples. |
| `/dji/primary/image_raw` | `sensor_msgs/Image` | Decoded primary camera, BGR8. |
| `/dji/fpv/image_raw` | `sensor_msgs/Image` | Decoded secondary logical stream, BGR8. |
| `/dji/diagnostics` | `diagnostic_msgs/DiagnosticArray` | Bridge health. |
| `/map/cloud` | `sensor_msgs/PointCloud2` | Existing downsampled map, latched. |
| `/dji/navigation/pose` | `geometry_msgs/PoseStamped` | Aircraft pose in the local map frame. |
| `/dji/navigation/path` | `nav_msgs/Path` | Bounded path in the local map frame. |

FPV is fully wired, but `/dji/fpv/image_raw` remains empty until the Android
transport actually sends valid secondary RTP packets to port `5610` and the
native receiver relays them to `5612`.

## Map coordinates and quality

Latitude/longitude are projected into UTM 29N and the map's recorded
translation is subtracted. `aircraft.altitude_m` supplies local map Z. RTK
vertical altitude remains raw diagnostics until its datum is calibrated to the
map. RTK is selected only when the fusion coordinate is finite and DJI reports
it in use; GPS is a valid fallback, so loss of RTK alone does not stop the path.
